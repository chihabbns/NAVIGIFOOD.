## 1. نظرة عامة على المشروع

**NAVIGUIFOOD** هو تطبيق ويب تم بناؤه لمحاربة هدر الطعام في الجزائر.

**المشكلة:** تقوم المطاعم، الفنادق، المخابز، والأسواق برمي كميات كبيرة من الطعام يومياً لأنه لم يتم بيعه في الوقت المناسب.

**الحل:** يوفر الموقع سوقاً لهذه الجهات لبيع فائضها بخصومات كبيرة (50-70%) قبل انتهاء صلاحيته. هذا يحول "الخسارة" إلى "قيمة" للمجتمع.

---

## 2. أهداف المشروع
- **تقليل هدر الطعام:** المساعدة في التخلص من الفائض بطريقة مربحة ومسؤولة بيئياً.
- **توفير المال:** تمكين ذوي الدخل المحدود والطلاب من الحصول على وجبات عالية الجودة بأسعار رمزية.
- **التحول الرقمي:** إدخال الحلول التقنية في قطاع الإطعام التقليدي في الجزائر.
- **الوعي الاجتماعي:** تعزيز ثقافة الاستدامة والحد من الإسراف.

---

## 3. التقنيات المستخدمة

*   **الواجهة الأمامية (Frontend):** HTML5, CSS3 المخصص بالكامل.
*   **اللغة البرمجية:** Vanilla JavaScript (ES6+).
*   **الخلفية والخدمات (Backend):** [Supabase](https://supabase.com/) (قاعدة بيانات PostgreSQL سحابية).
*   **المصادقة:** نظام Supabase Auth المدمج.
*   **الخرائط:** Google Maps Embed API لعرض المواقع.
*   **الأيقونات:** FontAwesome 6.0.

## 5. قاعدة البيانات — Supabase

يستخدم المشروع **3 جداول رئيسية**:

### جدول: `profiles`
يخزن معلومات المستخدمين (مرتبط بـ Supabase Auth).

| العمود | النوع | الوصف |
|--------|------|-------------|
| `id` | UUID | معرف المستخدم (يطابق معرف نظام المصادقة) |
| `name` | text | الاسم الكامل |
| `email` | text | البريد الإلكتروني |
| `role` | text | دور المستخدم (`buyer`, `restaurant`, `hotel`, إلخ) |
| `points` | integer | نقاط الولاء والمكافآت |

### جدول: `food_items`
يخزن قائمة الوجبات المعروضة.

| العمود | النوع | الوصف |
|--------|------|-------------|
| `id` | UUID | المعرف الفريد للوجبة |
| `donor_id` | UUID | معرف المزود الذي أضاف الوجبة |
| `title` | text | اسم الوجبة |
| `price` | number | السعر المخفض بالدينار الجزائري |
| `location` | text | موقع الاستلام |
| `time_left` | text | الوقت المتبقي قبل انتهاء العرض |

## 6. شرح ملفات الجافا سكريبت بالتفصيل

### `js/data.js`
يحتوي على البيانات الثابتة للأصناف.
```javascript
const foodItems = []; // فارغ — كل البيانات الحقيقية تأتي من Supabase

const categories = [
  { name: "Restaurants", icon: "fas fa-utensils", link: "restaurants.html" },
  { name: "Hotels",      icon: "fas fa-hotel",    link: "hotels.html" },
  // ...
];
```

### `js/ads.js`
**الغرض:** إدارة لافتات الإعلانات الممولة في الصفحة الرئيسية.
**الدوال الرئيسية:**
- `initAdsSection()`: تهيئة شبكة الإعلانات.
- `renderAds()`: بناء بطاقات HTML لكل إعلان.

### `js/main.js` ⭐ (الملف الأساسي — أكثر من 1000 سطر)
يحتوي على المنطق المركزي للموقع.

| الدالة | وظيفتها |
|----------|-------------|
| `initThemeToggle()` | التبديل بين الوضع المظلم والفاتح وحفظ التفضيلات. |
| `fetchFoodItems()` | جلب بيانات الطعام من Supabase وتصفيتها. |
| `renderFoodCards()` | بناء بطاقات الوجبات ديناميكياً وعرضها. |
| `handleSearch()` | معالجة البحث المتقدم حسب الكلمات المفتاحية والموقع. |

## 7. نظام نقاط المكافآت (Loyalty System)
يحتوي الموقع على نظام مستويات للمستخدمين (VIP Levels):
- **المستوى البرونزي:** المستوى الأساسي.
- **المستوى الفضي:** يتطلب 1000 نقطة (يفتح خصومات إضافية).
- **المستوى الذهبي:** يتطلب 3000 نقطة (أفضل الميزات والخصومات).

## 8. أسئلة المناقشة المتوقعة

**س: لماذا اخترت Supabase بدلاً من PHP أو Node.js؟**
*ج: اخترت Supabase لأنها تقدم نموذج Backend-as-a-Service (BaaS) يعتمد على PostgreSQL. هذا يتيح سرعة هائلة في التطوير، أماناً عالياً عبر نظام RLS، ودعماً للبيانات اللحظية (Real-time) دون الحاجة لإدارة سيرفرات معقدة.*

**س: كيف يتم التعامل مع الصور؟**
*ج: حالياً يتم تخزين روابط الصور في قاعدة البيانات، ويتم استدعاؤها من مجلد `assets/images` أو من روابط سحابية لضمان سرعة تحميل الموقع.*
